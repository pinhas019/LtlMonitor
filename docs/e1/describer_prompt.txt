Skill Description:
"The humanoid robot walks to a goal point it has been commanded to reach, in a room that
may contain obstacles, while a navigation planner chooses its path and steers it.

The skill begins when a goal has been commanded. The robot first gets going: it starts
moving and begins to close the distance to the goal; this should happen within about 15
seconds. It then walks towards the goal, steadily getting closer, for at most about 60
seconds. It finishes by arriving within half a metre of the goal.

Throughout the whole skill the robot must stay upright -- falling over is a safety
failure that must stop it at once -- and it must never come dangerously close to an
obstacle, which is also a safety failure.

While it is walking, the robot must keep getting closer to the goal. Sustained failure to
get any closer while still away from the goal means the skill has failed, even if the
planner believes it is still following its path: the robot may be stalled, slipping or
blocked.

The skill succeeds when the robot is within arrival distance of the goal and still
upright. The monitor checks the robot once per second."

Available sensor fields (the evaluator reads exactly these, nothing else):
  angular_vel                  - float, rad/s. Yaw rate of the base.
  base_height                  - float, metres. Height of the robot base above the odometry origin plane. Drops sharply if the robot falls or collapses.
  base_pitch                   - float, radians. Pitch of the robot base. 0.0 is level.
  base_roll                    - float, radians. Roll of the robot base. 0.0 is level.
  closing_speed                - float, m/s. How fast the robot is closing on its commanded goal: the drop in dist_to_goal per second since the previous tick. Positive while approaching, about 0 when stalled, negative when moving away. Measured from odometry against the commanded goal, not reported by the planner.
  dist_to_goal                 - float, metres. Straight-line distance in the ground plane from (pos_x, pos_y) to (goal_x, goal_y), recomputed once per tick from those four keys. Height is ignored deliberately: the z of a commanded waypoint is whatever the publisher stamped it at, not ground the robot has to cover. Until a goal has been commanded this reads as the distance back to the odometry origin, so a rule that treats a small value as 'arrived' must also establish that a goal exists.
  dist_to_next                 - float, metres. Straight-line distance in the ground plane from (pos_x, pos_y) to (next_x, next_y), recomputed once per tick. The intermediate point usually moves ahead as the robot advances, so this distance staying constant is normal and is NOT a sign of a stall -- progress is measured against the goal (closing_speed, no_progress).
  goal_active                  - bool, true once a navigation goal has been received this episode. Until then goal_x/goal_y hold their defaults and dist_to_goal is the distance back to the odometry origin, not to a goal.
  goal_x                       - float, metres. X of the point the robot has been COMMANDED to drive to, in the same odometry frame as pos_x. This is the target handed to the navigation algorithm, never the algorithm's own account of where it thinks it is going. 0.0 until a goal has been commanded, which is the odometry origin and not a way of saying 'no goal'.
  goal_y                       - float, metres. Y of the commanded goal point, in the same odometry frame as pos_y. Same source and same caveat as goal_x.
  image_similarity_to_goal     - float, 0.0-1.0. Visual similarity between the current camera view and a reference photo of the goal.
  linear_vel                   - float, m/s. Forward velocity of the base.
  min_range                    - float, metres. Distance to the nearest obstacle ahead within the 0.1-1.5 m height band. 10.0 means nothing was detected.
  next_x                       - float, metres. X of the intermediate point the robot is currently being sent to on its way to the goal, in the same odometry frame as pos_x. It is where the robot is being sent next, never a report of whether the navigation algorithm thinks it is succeeding. Where no intermediate point exists it equals goal_x.
  next_y                       - float, metres. Y of the intermediate point, in the same odometry frame as pos_y. Same source and same caveat as next_x.
  no_progress                  - bool, true when a goal is active, the robot is still farther than the arrival radius, and it has not closed on the goal for a sustained period (debounced over seconds). Derived from odometry, so it fires even while the planner reports that it is following a path.
  pos_x                        - float, metres. X of the robot base in the ODOMETRY frame (odom -> base_link), whose origin and axes are wherever the robot was when odometry started. It drifts with the odometry source and is not comparable across runs or to a map frame, so a rule may compare it to another quantity in the same frame (a commanded goal, an earlier position) but never to an absolute place in the world.
  pos_y                        - float, metres. Y of the robot base in the odometry frame, positive to the robot's left at the moment odometry started (ROS REP-103 right-handed, X forward, Y left, Z up). Same frame and same caveats as pos_x.
  pos_z                        - float, metres. Z of the robot base in the odometry frame, positive up. Height above the odometry origin plane, not above the ground the robot is currently standing on -- on a slope or a stair the two differ.
  upright_flag                 - float, 1.0 if the base is within tilt and height limits, else 0.0.
  yaw                          - float, radians in [-pi, pi]. Heading of the robot base about the odometry frame's Z (up) axis, ZYX/aerospace convention. 0.0 means facing along the odometry frame's +X axis and positive is counter-clockwise seen from above. It WRAPS: -3.13 and 3.13 are four hundredths of a radian apart, so a rule that subtracts two yaws without wrapping the difference is wrong twice per revolution.
