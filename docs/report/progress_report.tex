\noindent
A free-language description of a robot skill is compiled into a runtime
monitor---progress phases, LTL guards, named failure modes---which then watches the
skill run. It now runs on a Unitree G1 and its recordings replay deterministically; the
navigation experiment the central claim rests on has not run.

\smallskip\noindent
The separation that organises the system is \emph{adapter per embodiment, spec per
skill}: the engine is skill-agnostic by design. Two worlds exercise it---a
continuous-physics MiniGrid the monitor can drive at will, and the G1, an embodiment it
does not---and both are held to an \emph{equivalence oracle}:
Python\,$\leftrightarrow$\,C++ physics parity in the simulator,
live\,$\leftrightarrow$\,replay verdict equality on the robot.

\section{The continuous-world MiniGrid}

\textbf{What it is.} A continuous-physics layer over Farama MiniGrid that reuses the
discrete layouts: the agent acts through a continuous four-vector over a float pose, and
one step integrates a sweep of micro-steps rather than producing one successor state.
Two backends implement the physics---a pure-Python reference and a pybind11 C++
core---and parity tests are the only thing keeping them identical. The multi-agent
variant---$N$ agents, inter-agent collision, cooperative box pushing---is what the
monitor stack sits on.

\textbf{The extensibility argument.} Hazards---wind, pothole, lava, slippery---are
subclasses of a common base, each owning its physics effect, its monitoring category and
the containment flags it emits. That dictionary is what the monitor consumes, so a new
hazard type is a new subclass, not a monitor change---the environment-side twin of
adapter-per-embodiment.

\textbf{Status.} 155 tests pass with one real failure: the backends resolve a wall
contact to $4.74$ and $4.749$---a default-value drift in the integration step, not a
physics disagreement. No measured monitoring outcome yet; the contribution here is the
substrate.

\section{What the monitor is}

Each formula becomes its own B\"uchi automaton via Spot~\TODO{version}
\cite{duretlutz2022spot}, run alongside the others rather than as a product---which is
what makes attribution to a \emph{named} failure mode possible. Verdicts are
three-valued in the shape of Bauer et al.'s LTL$_3$ \cite{bauer2011runtime}, with the
correction in Section~\ref{sec:defects}. Progress is represented twice: as a nested-$F$
milestone chain, and as a phase machine with invariant and timing constraints. Faults
are graded, on a six-step ladder from \textsc{continue} to \textsc{abort}. A stale
proposition is \textsc{unknown} rather than false, so a safety guard cannot be
discharged by a sensor outage.

\section{The claim, and the check behind it}

The contribution is a validation oracle for skill-agnostic synthesis: a generated spec
is mechanically checked to reference only the sensor keys the adapter's declared schema
provides. The check is free-variable and sound by construction---an undeclared key raises
an error under a builtins-free evaluation---so it cannot false-negative. Two concessions:
soundness holds only over propositions carrying an executable rule, so it is bought with
coverage; and the oracle catches the \emph{unexecutable}, never the \emph{wrong}. The
repair loop it feeds is a standard pattern and is not claimed. Against the nearest prior
work \cite{english2025ginsign}, grounding targets a live adapter schema rather than one
fixed at inference, the check is sound rather than learned, and evaluation is on a
robot.

\section{First result on hardware}

The system was split across two tiers: clock, evaluator and recorder on the robot, so
the truth record reaches robot-local disk; monitor, console and replay on the
development machine. It produced 26 ticks and 26 observations, a position coordinate
advancing from 0.1 to 25.0, and an episode that replayed to 26 identical verdicts and no
differences---the acceptance test for the hardware-agnosticism claim. The caveat belongs
beside it: the stimulus drove two of the eight propositions the spec needs, so every
verdict was undecided in the idle phase---determinism on a thin trace---and nothing that
can move the robot was started.

\section{High-fidelity simulation}

\textbf{Done.} Three adapter descriptors---real G1, MuJoCo and Isaac Lab---expose an
identical 21-key schema over entirely different topics, so one monitor and one spec run
across all three unchanged; the identity is checked, not asserted. The Isaac
sensor bridging is settled: base pose arrives only as a transform and lidar as a point
cloud, and the evaluator reads that cloud through the same height-band filter it uses on
the robot, with no intermediate scan.

\textbf{Now.} The skill under test is still moving---TRAV changes week to week---and a
simulator running the robot's own stack is the only place to exercise the monitor
against those changes at episode scale. The purpose is re-executing counterfactuals, not
visualisation, so it is gated on fidelity validation: reproduce recorded outcomes first,
and report how many episodes are excluded. Two things block that. The Isaac descriptor
monitors Nav2 while the robot runs TRAV's planner, and the simulator has to run the
stack the robot runs; and scenario reset does not exist---the episode driver publishes a
scenario and waits on a completion flag the Isaac side has yet to implement.

\section{Two defects: one found by running it, one by reading}
\label{sec:defects}

\textbf{Found by instrumentation; fixed.} The sensor-state tick had no call sites, so
sensor evaluation returned schema defaults for the life of the process---a plausible,
entirely constant dictionary, with minimum range at its ``nothing nearby'' default, so
collision risk could never fire. Freshness stamping still worked, so confidence read
healthy throughout. Twenty odometry messages left the position at 0.0; one tick, 19.0.

\textbf{Found by reading; not yet fixed.} Twenty papers were read this period; the
review ranks nine defects in our own code. The headline one: status is reported
\textsc{accepted} whenever the automaton sits in an accepting state, which the docstring
wrongly reads as the property holding over the observed prefix. A B\"uchi accepting state
is not a good prefix, and $G(\lnot p)$ has no good prefixes at all---so a safety monitor
reports \textsc{accepted} before seeing anything, and both named failure modes have that
shape. The fix is per formula class: a monitor construction for safety, a corrected
B\"uchi path for progress.

\section{What has not run, and when it will}

The G1 \emph{navigation} experiment has not run. Planner independence is designed and
unimplemented, and this period showed why: the first phase gates on \emph{navigation mode
is automatic and waypoint count is positive}, so manual mode blocks the automaton
whatever the waypoints---the gate reads the planner's self-report, not the robot's
sensors. Five of the eight propositions are coupled that way---the same coupling that
keeps the Isaac descriptor pointed at Nav2. A second gap: minimum range is folded by
last-value from a 10\,Hz source against a 1\,Hz tick, so collision risk can miss a
transient obstacle. 1242 tests pass, none skipped and none exercising the ROS layer.
